# خطة تنفيذ بوابة صاحب الكافيه — CupBack

> **النطاق:** بوابة الويب الخاصة بمالك الكافيه وفريقه فقط. لوحة أدمن CupBack مؤجلة لمرحلة لاحقة.
> **الحالة:** متطلبات V1 محسومة حسب توجيه صاحب المشروع بتاريخ 11 نوفمبر 2026.

## الهدف

إنشاء لوحة ويب عربية/إنجليزية تتيح لمالك الكافيه إدارة العمليات والموظفين والرواتب والمنيو والمخزون والعملاء والعروض والولاء، وتخصيص صفحة كافيهه الظاهرة داخل تطبيق CupBack. كل عمليات القراءة والكتابة محصورة في الكافيه الذي يملكه المستخدم أو يملك صلاحية العمل عليه.

## قرارات V1 المعتمدة

- المستخدم المستهدف هو مالك الكافيه، مع حسابات موظفين بصلاحيات يحددها المالك.
- لوحة أدمن المنصة (CupBack Super Admin) ليست ضمن هذا التنفيذ.
- فرع واحد للكافيه في V1، بما يتفق مع `docs/PROJECT_SCOPE.md`.
- الرواتب شهرية.
- لا يوجد حضور أو انصراف أو جداول ورديات في V1.
- تسجيل صرف المرتب يكون يدويًا كدفعة نقدية. لا توجد مدفوعات إلكترونية في V1.
- تقارير المبيعات تدعم يومًا واحدًا، شهرًا، أو فترة يحددها المستخدم بتاريخ بداية ونهاية.
- صاحب الكافيه يخصص الخطوط والألوان والصور في صفحة كافيهه فقط. لا يغير هوية واجهة CupBack العامة.
- يستطيع المالك استعراض عملائه داخل كافيهه وإنشاء خصومات موجهة لفرد أو شريحة، مع مشاهدة تاريخ الطلبات والخصومات المستخدمة.
- الأسعار والخصومات والاستحقاق المالي تحسب وتتحقق من جهة الخادم عند ربط الـAPI.

## الأدوار والصلاحيات

| الدور | النطاق |
|---|---|
| `cafe_owner` (دور المنتج) | إدارة كاملة لكافيهه: الإعدادات، المستخدمون، الرواتب، المنتجات، العروض، العملاء، والتقارير. وثائق الأمان الحالية تستخدم `cafe_manager` كمدير كامل؛ يجب اعتماد اسم واحد أو ربط دور المالك به قبل ترحيل الصلاحيات. |
| `cafe_manager` | صلاحيات يحددها المالك؛ لا يستطيع منح نفسه صلاحيات أو الاطلاع على كافيه آخر. |
| `cafe_staff` | مهام تشغيلية محددة مثل الطلبات أو توفر المنتجات، وفق الصلاحيات المسندة. |
| `platform_admin` | خارج بوابة الكافيه الحالية؛ ينفذ لاحقًا في لوحة مستقلة. |

يجب فرض الصلاحيات على API والخادم وقاعدة البيانات، بالإضافة إلى إخفاء عناصر الواجهة. لا تعتبر حماية الواجهة وحدها آلية تفويض.

## تفاصيل الشاشات والتفاعلات

### 1. الدخول والحساب

- تسجيل الدخول الآمن، استعادة كلمة المرور، وتسجيل الخروج.
- إظهار/إخفاء كلمة المرور، اختيار العربية أو الإنجليزية.
- رفض الوصول برسالة واضحة عندما لا يكون المستخدم نشطًا أو لا يملك عضوية في الكافيه.
- لا تعرض البوابة بيانات تجريبية بصفتها بيانات حقيقية. عند العمل دون API يظهر شريط «وضع تجريبي».

### 2. الرئيسية

بطاقات: مبيعات اليوم، عدد الطلبات، متوسط قيمة الطلب، عدد الطلبات الجديدة/الجارية/الجاهزة، أكثر المنتجات مبيعًا، وتنبيهات العروض أو الأصناف النافدة.

الأزرار والفلاتر: `اليوم`، `7 أيام`، `هذا الشهر`، `فترة مخصصة`، `عرض الطلبات`، `إضافة منتج`، `إنشاء خصم`، `فتح/إغلاق الكافيه`.

### 3. الطلبات

قوائم حسب الحالة: جديد، مقبول، قيد التحضير، جاهز، مكتمل، مرفوض. بطاقة الطلب تعرض الاسم والرقم والوقت والأصناف والتخصيصات ونوع الاستلام وطريقة الدفع والخصم والإجمالي.

الأزرار: `قبول`، `رفض` (يتطلب سببًا)، `بدء التحضير`، `جاهز للاستلام`، `تأكيد استلام الكاش` (للمخول وبعد القبض الفعلي فقط)، `التفاصيل`، `طباعة الإيصال`. البحث والفلاتر حسب رقم الطلب والتاريخ والحالة وطريقة الدفع. الأحداث تصل لحظيًا عبر قناة موثقة ومقيدة بعضوية الكافيه.

### 4. المنيو والمنتجات والتوفر

إدارة التصنيفات، المنتجات، الصور، الوصف، السعر، الأحجام، مجموعات الإضافات وقواعد الاختيار. المنتج المؤرشف يبقى محفوظًا في لقطات الطلبات القديمة.

الأزرار: `إضافة تصنيف`، `إضافة منتج`، `تعديل`، `نسخ`، `ترتيب`، `رفع صورة`، `حفظ`، `إلغاء`، `أرشفة`، `متوفر`، `نفد مؤقتًا`، وفلتر `النواقص فقط`.

### 5. العملاء والخصومات الفردية

دليل خاص بعملاء الكافيه فقط. يعرض الاسم ووسيلة التواصل المسموح بها، عدد الطلبات المكتملة، إجمالي الإنفاق، آخر طلب، الشرائح/الحالة، وحالة الحظر داخل الكافيه.

صفحة العميل تحتوي سجل طلباته وعروضه ومكافآته في الكافيه. الأزرار: `عرض السجل`، `إنشاء خصم لهذا العميل`، `إيقاف الخصم`، `حظر` (سبب إلزامي وصلاحية خاصة)، `إلغاء الحظر`.

الخصم الموجه يحدد نوعه (نسبة مئوية أو مبلغ ثابت أو منتج مجاني)، قيمته، المنتجات/التصنيفات المشمولة، تاريخ الصلاحية، الحد الأدنى للطلب، عدد مرات الاستخدام، وهل يسمح بدمجه بعرض آخر. يعرض النظام معاينة لشروطه قبل نشره. يثبت الخادم أهلية العميل ويحسب السعر النهائي؛ لا يخصم المتصفح قيمة مباشرة.

### 6. العروض وبرامج الولاء

العرض يحدد الاسم والوصف، نوع الخصم، الجمهور (عميل محدد أو شريحة)، المنتجات والتصنيفات، جدول الأيام والساعات، فترة الصلاحية، حد الاستخدام، الحد الأدنى للطلب وقواعد الدمج.

الأزرار: `إنشاء عرض`، `حفظ كمسودة`، `معاينة`، `نشر`، `إيقاف مؤقت`، `نسخ`، `إنهاء`.

برنامج الولاء يحدد عدد الطلبات في الدورة، نوع المكافأة ونطاقها. الأزرار: `إنشاء برنامج`، `تعديل`، `تفعيل/إيقاف`، `معاينة ما يراه العميل`.

### 7. الموظفون

إضافة الموظف وربطه بالكافيه وتفعيل أو إيقاف حسابه. المالك يسند صلاحيات منفصلة للطلبات، تأكيد الكاش، المخزون، المنيو، العملاء، الحظر، التقارير، والرواتب. لا يوجد حضور أو انصراف أو ورديات في V1.

الأزرار: `إضافة موظف`، `دعوة`، `تعديل البيانات`، `تعديل الصلاحيات`، `إيقاف الحساب`، `إعادة تفعيل`، `إزالة من الكافيه`، `عرض سجل النشاط`.

### 8. الرواتب والدفعات النقدية

ملف الموظف يحفظ الراتب الشهري المتفق عليه وسجل الدفعات. الدفعة تحتوي الشهر المستحق، المبلغ بالجنيه/القرش، التاريخ، المستلم، ملاحظات، ومن سجلها. يدعم V1 دفعة كاملة أو عدة دفعات نقدية للشهر نفسه، مع المتبقي وحالة الشهر: غير مدفوع، مدفوع جزئيًا، مدفوع.

الأزرار: `تحديد الراتب الشهري`، `تسجيل دفعة نقدية`، `عرض الإيصال`، `طباعة كشف الشهر`، `تصدير`. تسجيل الدفعة لا يعني تحويلًا إلكترونيًا. تعديل أو حذف دفعة مسجلة لا يتم بصمت: ينشأ تصحيح/عكس موثق بسجل تدقيق مع السبب.

الوصول للرواتب مقصور على المالك ومن يمنحه صلاحية صريحة. لا تظهر الرواتب لبقية الموظفين افتراضيًا.

### 9. تخصيص صفحة الكافيه

المالك يغير اسم ووصف وصور وشعار وغلاف الكافيه، ألوان الصفحة، والخط من قائمة خطوط مرخصة ومدعومة في تطبيق الهاتف. الأزرار: `رفع صورة`، `قص`، `حذف`، `اختيار لون`، `اختيار خط`، `معاينة على الهاتف`، `حفظ كمسودة`، `نشر التغييرات`، `استعادة الافتراضي`.

تظهر معاينة قبل النشر. تحفظ إعدادات المظهر لكل كافيه منفصلة. تغييرات الخطوط والألوان لا تمتد إلى واجهة CupBack العامة أو كافيهات أخرى. الخط العربي الافتراضي المقترح Cairo، واللاتيني Plus Jakarta Sans؛ لا يسمح باختيار خط لم يدمج في تطبيق العميل.

### 10. تقارير المبيعات

اختيار سريع: `اليوم`، `هذا الشهر`، أو `فترة مخصصة` عبر `من تاريخ` و`إلى تاريخ` ثم `تطبيق`. فلاتر إضافية للحالة وطريقة الدفع والتصنيف/المنتج.

المخرجات: إجمالي المبيعات، عدد الطلبات، متوسط الطلب، قيمة الخصومات، صافي المبيعات، تفصيل يومي، أفضل المنتجات، ومبيعات حسب طريقة الدفع. الأزرار: `تطبيق الفلاتر`، `مسح الفلاتر`، `تصدير CSV/Excel`، `تنزيل PDF`، `طباعة`.

يجب تعريف صافي المبيعات بوضوح والتمييز بين قيمة الطلبات المكتملة والمبالغ المستردة/المرفوضة؛ التقرير المالي مصدره الخادم، وليس تجميع أرقام من الواجهة.

### 11. إعدادات الكافيه

بيانات الاتصال والوصف وساعات العمل وأيام الإغلاق مع دعم فترة تعبر منتصف الليل. أزرار: `تعديل`، `حفظ`، `إلغاء`، `فتح الآن`، `إغلاق الآن`.

## الهوية البصرية

- RTL افتراضيًا، وتحويل كامل إلى LTR للإنجليزية.
- واجهة CupBack: كريمي `#F9F7F4`، بني قهوة `#190E08`، كراميل `#D87D38`، أبيض للبطاقات، وألوان حالة واضحة للنجاح والتحذير والخطأ.
- النص العربي: Cairo؛ الإنجليزية والأرقام: Plus Jakarta Sans؛ عنوان عرض عربي مميز فقط عند توفر خط مرخص ومدمج.
- دعم لوحة المفاتيح، حالات التركيز، وتخطيط متجاوب للديسكتوب والتابلت.
- مظهر الكافيه المخصص يؤثر في صفحة الكافيه للعميل فقط، لا في لوحة الإدارة.

## نموذج البيانات المطلوب

`CafeMembership`، `CafeBranding`، `CafeCategory`، `Product`، `Variant`، `ModifierGroup`، `CustomerCafeSummary`، `CustomerBlock`، `Promotion`، `PromotionEligibility`، `LoyaltyProgram`، `CafeEmployee`، `EmployeePermission`، `MonthlySalary`، `SalaryCashPayment`، `AuditLog`.

كل سجل كافيه يحمل نطاق `cafe_id`. تستخدم المبالغ أعدادًا صحيحة بوحدة القرش وفق متطلبات المشروع. بيانات الرواتب والخصومات الفردية وسبب الحظر لا ترجع لمستخدم دون صلاحية.

## ترتيب التنفيذ

### المرحلة صفر — تأسيس وربط

1. اعتماد التقنية النهائية للبوابة والـAPI. التقرير الرئيسي يذكر Node/Supabase، ووثائق `docs/` تصف Laravel؛ يمنع بناء تكاملين متوازيين.
2. توحيد دور المالك مع الأدوار الحالية في `docs/SECURITY.md` (`cafe_manager`) وتحديد مصدر صلاحياته.
3. تثبيت مخطط المصادقة، عضوية الكافيه، واستخراج `cafe_id` من جلسة موثوقة.
4. اعتماد حالات الطلب وواجهات API والهوية البصرية ومصادر الخطوط.

### المرحلة الأولى — الهيكل والتشغيل اليومي

بوابة الدخول، التنقل والصلاحيات، الصفحة الرئيسية، الطلبات اللحظية، المنيو والتوفر، وإعدادات ساعات العمل.

### المرحلة الثانية — العملاء والنمو

CRM العملاء، الحظر، الخصومات الفردية والشرائح، العروض العامة، وبرامج الولاء.

### المرحلة الثالثة — فريق العمل والماليات

دعوة الموظفين والصلاحيات، سجل التدقيق، رواتب شهرية، دفعات كاش جزئية/كاملة، وكشوف شهرية.

### المرحلة الرابعة — مظهر الكافيه والتقارير

رفع الصور والتحقق منها، إعداد الألوان والخطوط، معاينة صفحة العميل، النشر، وتقارير المبيعات ذات الفترات والفلاتر والتصدير.

### المرحلة الخامسة — إطلاق بوابة المالك

مراجعة عزل بيانات الكافيه، الصلاحيات، خصوصية العملاء والرواتب، سجل العمليات المالية، RTL/LTR، وتحمل الشبكة الضعيفة. لوحة أدمن CupBack تبقى مرحلة مستقبلية مستقلة.

## قيود حالية قبل الربط الحقيقي

- المستودع يحتوي تطبيق Flutter تجريبيًا ولا يحتوي حاليًا Backend فعليًا أو تطبيق ويب مستقلًا.
- لا يجوز الادعاء بأن واجهة تجريبية غير متصلة تستطيع تعديل بيانات التطبيق الفعلية.
- الاختيارات المقترحة في `docs/ARCHITECTURE_DECISIONS.md` و`docs/OPEN_QUESTIONS.md` التي ما زالت معلّقة يجب اعتمادها قبل تنفيذ خدمات الإنتاج المتأثرة بها.
- تعديل خط صفحة العميل يتطلب دعم الخط داخل تطبيق Flutter وإلا لا يمكن تطبيق اختيار الويب عليها.

## شروط قبول V1

- مالك الكافيه يصل لكل إعدادات كافيهه، ولا يستطيع الوصول إلى كافيه آخر بتغيير معرف في الطلب.
- الموظف لا يرى ولا ينفذ ما لا تسمح به صلاحياته، ويظل تحقق الصلاحية خادميًا.
- تسجيل دفعة راتب ينقص الرصيد المستحق للشهر الصحيح، ويبين أنها كاش ويسجل الفاعل والتاريخ.
- التقارير تعرض يومًا أو شهرًا أو نطاقًا مخصصًا، وتطبق الفلاتر على البيانات نفسها.
- يمكن إنشاء خصم لعميل بعينه أو شريحة، مع شروط استخدام وحدود وبيان الاستخدام الفعلي.
- معاينة المظهر لا تنشره؛ النشر يؤثر على الكافيه نفسه فقط.
- لا توجد شاشات أو أزرار حضور/انصراف أو دفع إلكتروني للرواتب في V1.
- واجهة أدمن المنصة ليست ضمن بوابة صاحب الكافيه.
